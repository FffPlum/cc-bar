# 应用与授权重构验证记录

日期：2026-10-31。分支：`feature/deepseek-accounts`。本次修改未提交、未发布。

## 实现结果

- 主窗口只有一个常驻侧栏：应用在上，授权中心、用量统计、设置在下。
- 应用供应商配置与厂商授权分离；同一供应商的模型合并展示。保存配置方案与应用切换分为两步。
- DeepSeek 提供 API Key 和官方浏览器授权入口；本机识别到的 DeepSeek Key / DSH grant 可查询余额。已有厂商图标复用，仅新增 DeepSeek、Grok、Gemini 的 openbrand 来源记录。
- 菜单栏和悬浮窗由账号显示选项控制；导入的 Codex 账号新增两个显示选项。
- 用量统计的配置按钮切换应用及概览、对话、项目、额度；全局设置仅保留外观、数据、通用。
- 源码迁入 `Sources/`、测试迁入 `Tests/`；`CCBarConfiguration` 是独立 Swift Package target。206 个原有受版本控制文件的迁移目标逐一检查存在。

## ub-mode 操作与原因

按用户指定的 ub-mode 执行实现后的结构审查与修正：

| 操作 | 原因 / 验证 |
|---|---|
| 配置领域独立成库 | TOML / JSON / JSONC / YAML / dotenv 解析、协议与地址校验不依赖 SwiftUI / AppState，可用临时目录验证 |
| API 地址约束集中到 APIEndpoint | 同一处判断安全地址、同源凭据使用，避免表单与写入规则不一致 |
| 复用 PrivateCredentialFileStore 与 APISecretFileStore | 新授权不再依赖 DeepSeek 名义的存储；共用文件权限、原子写和删除行为 |
| 提取 AccountDisplayControls、WorkspaceHeader、SupplierIcon | 账号行和应用页共用控件，移除设置页内的账号实现和失效的用量行分支 |
| 弹窗由 EditorRequest 单一状态驱动 | 实机复现首次点配置得到空表单；修复后首次打开即带入原模型、地址、授权与上下文 |
| 同厂商多模型合并 | 实机发现 Kimi 每个模型重复大卡片；合并后厂商头部只显示一次 |
| 旧开关只迁移一次 | 防止每次重启重新合并额度与用量偏好；测试覆盖两种相反设置 |
| 配置写入前验证原文、备份、逐文件原子写 | 并发编辑拒绝覆盖；原登录文件与无关字段保留 |
| 禁止静默替换异常容器 | 错误格式的已有配置不会被转换为空字典后覆盖 |
| 保留 JSON 大整数 | 避免 Double 中间表示改变无关配置数据 |
| 排除环境变量 / 文件 / shell 凭据引用 | 不把引用字符串误当密钥导入，不执行配置中的命令 |
| 保留 Codex / Grok 原生登录 | 切回官方配置不会残留第三方模型；不改原有 auth.json |

技能提到的 `crapper`、`dryer`、`mutator` 在本次环境中没有可用工具或命令，因此没有生成复杂度、重复率或变异测试分数。采用代码审阅、行为测试和实际界面复现；不声称做过这些工具检查。测试并非全部采用先红后绿流程，已记录的失败包括 macOS 系统路径别名处理和首次编辑表单；修复后重新验证。

## 实际界面验证

在本工作区编译产物中检查，未覆盖 `/Applications/CCBar.app`：

- 全局导航识别本机 Codex、Claude Code、Kimi Code 和 DeepSeek Harness。
- 授权中心显示 DeepSeek API Key 与 DSH 来源账号，二者查询到有效余额；未把实际邮箱、密钥或余额写入本记录。
- Popover 可见独立 DeepSeek 品牌与两种授权余额。
- Kimi 原生多模型正确按供应商合并，当前模型有正在使用状态。
- 首次打开已有供应商配置表单正确预填；退出表单没有保存，没有切换用户正在使用的供应商。
- 统计配置面板可选择应用与四种子视图，并实际切换到了项目页。
- 设置只剩三个分类，新增品牌可在颜色设置中找到。

## 验证边界

- 未重新执行一整套真实浏览器授权 / 注销；回调、取消与认证请求由定向测试覆盖，已有 DSH 授权的官方余额请求已成功。
- 未用真实凭据切换所有外部 CLI；写入与恢复在临时目录测试，没有为验收改写用户的应用配置。
- Grok / Gemini 本机订阅登录只展示身份与状态；通用 OpenAI / Anthropic / Grok / Gemini Key 支持配置引用，暂未接入余额。
- 用户级配置可能被项目、环境或组织配置覆盖，界面提示重启并在原应用确认。
- 写入会重新排版配置，可能不保留注释；原文备份可查看。多文件写入不保证进程崩溃时的全局原子性。
- 不提供路由、聚合服务，不包含发版或安装包更新。

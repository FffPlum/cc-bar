# SQLite 用量明细缓存

日期：2026-11-02。分支：`feature/react-main-window`。状态：SQL 查询与前端结果缓存已落地，43 项 Swift、30 项 React 定向测试及指定 Debug 构建通过。

用户明确忽略旧 JSON 明细，首次从已接纳日志建立 SQLite 索引；随后要求对齐 cc-switch，启动不恢复全量明细，筛选、分页和明细聚合由 SQL 执行。

## 职责与流程

- `UsageService` 只常驻来源指纹、事务版本、覆盖及刷新状态。启动 `loadMetadata()` 不读取 `requests`；后台按现有 usageInterval 同步，逐个解析变化来源、提交并释放临时行，未变来源不重扫。
- `UsageRequestIndexStore` 保存系统 SQLite 数据库 `CCBar/usage-history/request-index.sqlite3`。旧 `request-index-v1.json` 不读取、迁移或删除；权威历史 `current.json` / `previous.json` 与远端日桶仍保留。
- `UsageRequestIndexQueries` 在后台 SQL 中筛选、分页、排序、计数和聚合。Host 不再持有请求全集、内存核验缓存或内存分页链。
- React Query 按完整查询条件缓存结果，切回缓存立即显示；新筛选/排序/翻页与后台刷新保留旧内容。失败标记旧结果并提供重试，旧游标不能继续翻页；隐私、语言、币种、时区或可见应用改变时隔离缓存。过期游标退回首页前强制首页缓存失效。

## 数据库与一致性

`sources` 保存应用来源指纹及不完整状态；`requests` 以 `(app,id)` 为主键，逐列保存会话摘要、模型、速度、日期、时间、Token、请求数、费用与计时；`cache_metadata` 保存事务版本。金额保持 Decimal TEXT，计数用 INTEGER64，计时是小型 JSON。应用/时间、应用/模型/时间、应用/模型/速度/日期索引服务范围与分区查询；旧 v1 库首次元数据加载时补查询索引，不在 Swift 恢复明细。

同一组指标、候选项、图表、覆盖和分页查询共享一笔读事务。SQL 将传入的权威日汇总放入临时表，分区 GROUP BY 后核验请求数及各类 Token 不超过已接纳历史；只返回聚合桶和当前页（最多 500 行）。精确金额使用自定义 Decimal 聚合与排序，首字时间、精确/估算生成速度遵守原阈值；小时区间由 Calendar 构造，支持夏令时。

完整自然日继续采用权威日汇总，部分日与小时采用 SQL 明细聚合；因此清理过日志的历史仍存在，但不伪造逐请求时间。会话摘要仅为当前页匹配已有元数据并生成不透明 ID，不保存路径、标题、正文或凭据。

导入在写入前检查候选来源不超出已接纳日桶，失败保留该来源旧行；查询也会排除不一致分区并报告覆盖缺口。`saveChanges` 只替换指定成功来源，失败来源仅更新覆盖状态；来源状态、明细与事务版本同事务提交。写入串行且核对输入版本，首建使用私有临时库提交后原子发布。

数据库和文件锁权限 0600，DELETE journal、FULL 同步，SQLite busy 等待 250ms；文件锁区分共享查询与排他写入，最长等待 500ms。连接与 statement 在后台操作内创建/释放，不跨任务传指针。

## 故障边界

- 缺失或确认损坏：仅重建派生索引；确认损坏的旧库隔离留存，有可能活跃的 journal/WAL/SHM 时不改名。
- 锁占用、权限、I/O、磁盘满或未来版本：保留数据库；查询抛错让前端保留成功结果，加载/写入失败延迟重试，不发布空结果。
- 来源暂时读失败：保留磁盘旧行和有效指纹，后台重试；不可恢复的明细缺口单独标记，不循环扫描。
- 权威日桶不因派生库故障而清空或全量重算。DSH、Cursor 与历史补录仍可能只有日级统计。

# Kimi 统计与额度页补齐执行计划

日期：2026-10-25。状态：已实施，Debug 构建及 287 项定向测试通过，真实界面待手动验收。主任务负责架构、审查补齐及验证，本地 Kimi Code CLI 执行主要实现；按用户后续要求使用 `kimi-code/k3.1-pro-highspeed`。

## 问题与证据

- `Pricing.pricingKey` 仅剥 `kimi-code/` 前缀，未将 Kimi Code 的 `k3` / `k3-256k` / `k3.1-pro*` 对应到公开 API 型号；本地表也没有 Moonshot 兜底价。订阅路由和有公开价的模型因此一起落为缺价。
- 本机新版日志同时存在 `kimi-code/k3`、`kimi-code/k3-256k`、`kimi-code/k3.1-pro-highspeed`、`kimi-code/kimi-for-coding`。当前 CLI 默认值是最后一种。请求级 `llm.request.model` 与 `usage.record.model` 相符，没有把 K3 统一误写成 kimi-for-coding 的证据。保留历史请求身份，不使用当前配置重命名历史。
- 官方模型配置文档当前将 `kimi-for-coding` 标为 K2.8 Preview；它不是 K3 / K3.1 的别名。该滚动路由没有核实到可靠的公开 API 价格，不能按 K3 猜价。
- 概览模型列使用单行中间截断，没有完整名称 tooltip。
- 设置与在线额度已接入 Kimi，但统计额度页、周期归属、账号历史系列和 AppState 记录链路仍排除它。用户已确认新增 Kimi 周期预估与额度变化图。

## 实施分项

1. **可靠参考计价**：在统一查价层以精确白名单对应 `k3` / `k3-256k` → `kimi-k3`，`k3.1-pro` → `kimi-k3.1-pro`，`k3.1-pro-highspeed` → `kimi-k3.1-pro-highspeed`。只改变价格查询键，不改变存储和显示的模型名；Highspeed 是独立模型费率，不能套 Codex Fast。添加核对过的美元/百万 Token 离线价：K3 为输入 3 / 输出 15 / 缓存读 0.30 / 默认缓存写 3；K3.1 Pro 为 2 / 10 / 0.20 / 2；Highspeed 为 4 / 20 / 0.20 / 4。订阅实际账单与 API 等值估算继续区分。
2. **无法计价的 Kimi 模型**：用户已明确选择，对概览模型行中完全无法计价的 Kimi 型号显示 `—` 并通过 tooltip 说明未公开参考价格，避免 `$0.00` 的免费错觉。不猜 K2.8 / 旧版 unknown 价格，不扩大到其他服务的既有显示规则。有价模型的新价格复用现有价格指纹与安全重算链，核查已有快照费用可以更新，源日志缺失时保留历史。
3. **完整名称**：模型维度名称与副标题使用系统 `.help` 展示完整模型及来源；提供商展开的模型行也补齐。继续使用原列表宽度和截断，不引入自制浮层。按用户后续要求，为 `kimi-for-coding` 增加「当前 K2.8 Preview」显示说明，保留原始路由；不能将滚动路由旧历史全认定为 K2.8，不改存储键、分组键、去重签名或价格键。英文对应 `currently K2.8 Preview`，不凭显示名猜价格。
4. **额度链路**：增加 Kimi 账号历史身份，直接复用凭据已有稳定账号键；成功刷新记录 5 小时/周额度历史和周期，缓存只在账号匹配且不早于已有历史及周期样本时，按原采样时间补记。失败与 429 不写伪样本、不清快照。切换账号保持历史分离。
5. **周期用量**：Kimi 日志中仅 `kimi-code/` 下六个已知官方订阅型号进入 Kimi 周期；DeepSeek、自定义渠道、旧版 unknown 均排除。复用逐会话贡献替换、周期重建与账号时间段归属。检查 Kimi 追加/重算不会漏记或重复累计周期用量。
6. **额度展示**：全部服务与 Kimi 单选均展示 5 小时/周周期卡及时间线，遵守服务可见性与用户排序。卡片宽屏最多四列，自适应换行。月窗口缺乏可靠周期长度，继续保留在线展示，不伪造周期预估。不伪造采集前的额度变化。新周期卡完全无法估算的费用同样显示 `—` 并提供说明。
7. **文档与回归**：同步产品需求、技术实现、界面布局及验证记录；补确定性价格、缺价、周期归属、账号隔离、刷新失败、重扫幂等回归用例。验证状态如实标记。

## 验收

- K3 / K3.1 三种公开费率按四类 Token 计算，费用不是 0；模型名称仍与历史请求一致。
- 同一会话切换 `kimi-for-coding`、`k3`、`k3.1-pro-highspeed` 时逐请求保留型号，不受当前 CLI 默认模型影响；不同型号分别聚合计价。
- kimi-for-coding 无公开价时明确无估算值；悬停可看完整模型和来源。
- Kimi 额度页可显示新采样、真实重置窗口及用满估算；新增服务卡后布局可读，Kimi CLI 的第三方模型不影响其订阅用量。
- 原有 Codex / Claude 周期、额度退避及删除日志后的历史保留保持有效。
- 先静态审查；构建和测试按项目规则征得同意后执行。手动验收通过 Xcode 运行，不替换用户安装的应用。

# React 用量统计仪表盘调整方案

日期：2026-11-02。分支：`feature/react-main-window`。依据用户提供的五张布局图，由 Codex 制定方案和验收，GPT-6.1 Terra 实现。现有未提交改动保留；不发布或替换已安装应用。

状态：实现与代码审查完成，Swift 68 项、React 54 项、SDK 15 项、额外纽约 DST 定向用例和指定 Debug 构建通过。视图/动画观感由用户验收，证据与数据边界见 [验证记录](验证记录-React主窗口.md#2026-11-02-用量统计仪表盘)。

## 页面与交互

1. 保留 cc-bar 全局侧栏及对话、项目、额度入口。统计概览采用新的全宽仪表盘，不复制参考应用的其他导航功能。
2. 固定页头显示「用量统计」、帮助、上次同步/刷新与视图选项。内容保持四周 20px 间距，浅深色沿用现有设计体系。
3. 筛选栏依次放时间范围、全部/应用图标、供应商/模型级联选择。时间弹层包含当天、近 24 小时、近 7/14/30 天、全部，支持起止日期与时分、月历及终点跟随当前时刻；取消不修改查询，确认后统一更新。
4. 单张汇总卡顶部四列为费用、请求数、Tokens、缓存命中率；选中指标切换下方图表。短范围按小时、较长范围按天展示，包含刻度、网格、零值日期和悬停明细；可折叠图表。
5. 全部时间展示按周排列的日热力图，每页 53 周，包含月份/星期、区间汇总、强度图例和日提示；更早记录按块追加，日期不重复。
6. 下方全宽卡片以请求日志、供应商、模型为页签，显示计数和可排序表格。请求记录使用宿主分页与跨页排序；聚合表包含请求数、费用、Tokens、成功率、输出速度和首字时间。1280px 逻辑屏宽下全部列保持可读。

## 数据与兼容性

- 增加 `window.usage.dashboard`、`window.usage.requests`、`window.usage.heatmap` 与对应 SDK 查询/响应校验。旧 overview/conversations/projects/quota 接口继续保留。
- 查询范围使用 `[from,to)`。近 24 小时按实际 86400 秒，其余自然日使用宿主时区；自定义起止为绝对时间，跟随当前时刻的终点由宿主解析。小时键不能在夏令时重复时发生碰撞。
- 截图中的供应商实际是用量来源，例如「Codex · 会话日志」。以真实应用/日志或远端计量来源筛选，不将当前 API Key 配置反推为历史供应商。
- 费用、速度、首字、缓存口径复用 Swift 聚合与格式化，前端不重新计算汇率或金额。成功率缺少完整失败分母时返回 `null` 并显示 `—`，不推断为 100%。
- 新增只读派生请求索引，复用扫描器读取规范化数值；Kimi 优先使用已提交事件。相同内容请求以出现序号区分，不以内容哈希去重。索引不修改原有日汇总、扫描游标、凭据或用户日志。
- 请求记录按应用/模型/速度/日期与权威日桶核对；超出已接纳汇总的候选分区不直接发布。缺失/删除的日志、日级补录及没有事件明细的远端历史保留为显式覆盖缺口，不伪造时间戳或按小时平摊。
- 全日统计保留权威日桶；部分日只能统计已核验事件，并明确提示无法精确定位的历史量。请求游标绑定查询、排序、版本与冻结区间，避免后台刷新或 follow-now 导致重复/漏项。
- 移动终点范围在可见页面每分钟刷新；固定自定义区间保持不变。更早热力图按展开块数保留，刷新后沿新的分页链重取，避免跨周产生缺口。过期筛选请求不得重置当前请求分页。
- 日志暂时读取失败时保留该来源之前的索引记录，并在后续查询重试；DSH/Cursor 固有的明细缺口不作为可重试错误。OpenCode/Antigravity 数据库更新早于正常扫描时，事件核验可能暂缓该分区。
- Cursor 全部时间仅包含已加载远端历史，53 周页触发有限区间补拉。旧持久化日桶没有原始时区信息，系统时区改变后无法保证旧日桶完整重映射，不自动改写历史。
- 不回传请求正文、真实路径或凭据；保留现有隐私模式、错误快照、限流与刷新策略。

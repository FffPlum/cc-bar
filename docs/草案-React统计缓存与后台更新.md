## 问题与参考

当前 `useHostResource` 在查询依赖变化时清空 data，`ResourceFeedback` 替换整页，筛选栏与图表因此反复卸载。日汇总和扫描进度已在 Swift 持久化，正常启动为增量扫描；新请求索引只有进程内缓存，三个仪表盘查询等待重放日志，放大了启动与切换的等待。页头还把普通 scanning 显示为「正在重新计算」。

已对照 cc-switch 公开源码（2026-11-02 读取 main，非固定版本）：

- [统计查询](https://github.com/farion1231/cc-switch/blob/main/src/lib/query/usage.ts)：完整筛选 queryKey、TanStack Query、keepPreviousData 和定时刷新。
- [统计页面](https://github.com/farion1231/cc-switch/blob/main/src/components/usage/UsageDashboard.tsx)：筛选状态与数据区域分离，应用分段选择有独立选中指示器。
- [日志同步](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/services/session_usage.rs)：日志解析结果入库，保存按文件增量游标；[启动调度](https://github.com/farion1231/cc-switch/blob/main/src-tauri/src/lib.rs) 在后台执行启动同步和定时兜底。

借鉴缓存和后台同步职责分离，保留 CCBar 的 Swift 业务与权威历史存储。后续按用户要求将明细持久化及查询迁入 SQLite，不改写已保存的历史用量。

## 实现方案

1. **前端查询缓存**：仅新统计仪表盘接入锁定版本的 TanStack Query v5。按 WindowAPI 会话、完整查询和展示上下文隔离；包含时间、应用、来源、模型、指标、排序和分页。正常有效期 60 秒，非活动查询保留 10 分钟；同键请求合并。用量事件令缓存过期并重取当前查询，可见页面定时更新，后台窗口不轮询。
2. **连续显示**：筛选栏持续挂载，点击立即反馈；已缓存筛选直接显示。新查询没有缓存时允许短暂保留上次内容，但明确标记正在切换、暂显示上次结果，并禁用旧数据的分页等动作。隐私、语言、币种/汇率、时区、应用可见性变化立即隔离旧上下文，不能借占位显示旧敏感数据。失败保留可用结果并标记上次筛选/分页，同时提供重试。
3. **索引持久化**：保存版本、来源指纹与最小统计字段，会话键只存摘要，不存路径、标题、正文或凭据；当前页返回后仅与已恢复会话元数据匹配，不存在时返回空会话链接。后续按用户要求改为 [SQLite 明细缓存](草案-SQLite用量明细缓存.md)，忽略旧 JSON 明细，首次后台重建；事务按来源更新。已确认损坏或指纹过期只重建派生索引，未来数据库版本保留并暂缓使用，不清空权威日桶。
4. **后台更新**：主历史就绪后后台只加载索引元数据，复用匹配来源；正常扫描完成后更新失效来源，继续遵循已有 usageInterval。显示接口同步返回元数据或待准备状态，不等待日志重放；明细筛选、排序、分页与聚合直接查询 SQLite，读事务返回汇总桶和当前页，不恢复全量明细。后台工作合并，逐来源解析、核对版本、串行提交并释放临时记录；临时失败保留可用记录并限制重试频率，防止失效通知形成循环。
5. **状态与过渡**：`coverage.refreshing` 区分正在准备明细与永久历史缺口；普通 scanning 文案改为同步。按钮保持统一 32px 尺寸与清晰选中态；使用短时 opacity/transform 反馈，不动画数字或表格布局，支持减少动态效果，键盘交互不添加位移动画。

## 验收

- A→B→A 缓存复用；同键去重；定时和事件失效重验；新筛选的晚到响应及旧游标错误不干扰当前结果。
- 隐私、语言、汇率、可见服务改变时不泄露或复用旧语义数据；后台刷新保持筛选弹层和热图展开状态。
- 重启直接复用有效派生索引，主历史未就绪不覆盖缓存；损坏/旧版本/来源变化/读取失败只影响派生数据，不触发 forceRescan。
- 新缓存 payload 不含原始会话键或路径；过期后台结果不得覆盖新代数据。
- 最小相关 Swift、SDK、React 回归与指定 Xcode Debug 构建；真实视觉和动画观感仍由用户验收。

# 本机签名与钥匙串访问验证

日期：2026-10-26。范围：本机固定自签名、Kimi 订阅与 Moonshot API 凭据缓存、拒绝授权后的暂停与显式恢复。

## 实现

- 一次性运行 `scripts/setup-local-signing.py`，创建并复用 `CCBar Local Signing`；私钥保留在用户钥匙串，本机 JSON 配置仅存公开指纹。信任设置仅用于当前用户的代码签名。重复执行已验证复用同一身份，不生成新证书。
- `scripts/build.sh` 本机自动读取固定身份，也可通过 `CCBAR_SIGN_IDENTITY` 指定；CI 不读取本机配置，默认仍为 ad-hoc。无效的指定身份在清理旧构建前失败，已验证旧构建保持不变。所有 Sparkle 嵌套组件和主 App 使用同一选定身份逐层签名。
- `CachedManagedKeychain` 按服务与账户缓存首次读取结果，写入和删除同步更新缓存；只用于 CCBar 自己管理的凭据，外部 CLI 凭据检测不变。每次请求后的凭据值校验保留，因此缓存更新和删除仍能阻止旧响应覆盖新身份。
- 拒绝、取消、钥匙串锁定／禁止交互后暂停读取，非秘密的暂停状态跨重启保存。普通刷新不清除暂停标记；设置账户菜单提供「重试钥匙串访问…」，显式恢复仍遵守账户 429 退避。额度和余额快照不因访问失败清空。

## 实测边界

固定自签名与完全免授权不是同一回事。本机两个内容不同、使用同一证书与标识签名的测试程序具有相同 designated requirement；但默认文件钥匙串项目仍受额外的 cdhash 分区限制。第二构建在禁止系统交互时读取第一构建创建的临时项目返回 `errSecAuthFailed`（-25293），相同安装路径也如此；恢复原构建读取和删除均成功。测试仅创建并删除专用临时项目，没有读取或修改用户真实凭据及其 ACL。

因此，固定证书保存了代码签名身份，不能承诺所有升级均不再询问。新构建首次访问旧凭据可能仍需授权；连续读取由缓存消除，拒绝后由暂停机制阻止再次询问。不以开放所有程序访问、清空分区列表或改写第三方凭据的访问控制来换取免弹窗。Apple 的实现见 [分区身份分类](https://github.com/apple-oss-distributions/Security/blob/main/securityd/src/clientid.cpp) 与 [分区校验](https://github.com/apple-oss-distributions/Security/blob/main/securityd/src/acls.cpp)。

已用仓库脚本生成 **v1.1.30 / arm64** 的 `dist/CCBar.dmg` 与 `dist/CCBar.app.zip`，主 App 的签名 Authority 为 `CCBar Local Signing`，designated requirement 绑定本机证书与 `com.nanvon.ccbar`。嵌套组件及主 App 严格签名验证、DMG 校验和、ZIP 完整性、工程 plist 与 `git diff --check` 均通过。未提交或推送。

- `CachedManagedKeychainTests`：并发读取只访问后端一次；写入与删除立即更新缓存；相同值不重复写入；拒绝、取消和禁止交互后跨重启暂停；显式重试恢复；失败写入不缓存新值；服务与账户相互隔离。
